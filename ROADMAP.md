# ROADMAP — сверка с жанром RTS, что делать дальше (этап 5 QA)

Только анализ. Мелкие безопасные улучшения из этого списка уже сделаны (отмечены ✅), крупные — только описаны.
Сеть в этом проходе не трогали.

## 1. Сравнение с типичными RTS-механиками

| Механика RTS | Есть в моде? | Комментарий |
|---|---|---|
| Выделение рамкой, Shift-добавление | ✅ да | рамка берёт героя, если центр тела в рамке |
| Группы Ctrl+цифра, вызов цифрой, двойное нажатие = камера | ✅ да | цифры `1..0` не настраиваются (только они и Esc зашиты) |
| Двойной клик = все такого же типа | ⚠ частично | выбирает всех героев того же выжившего «где бы ни были», а не «только на экране» |
| Move / Attack-move / Hold / Stop / Patrol | ✅ да | `Q E R T`, настраиваются |
| Очередь приказов (Shift) | ⚠ частично | работает; на экране рисуется только текущий отрезок, не весь маршрут |
| Формации | ✅ да | куча / линия / колонна (`N`); нет «перетащить линию» и поворота строя |
| Точка сбора, отход | ✅ да | одна общая точка |
| Экономика | ✅ упрощённо | общий кошелёк, найм, воскрешение; нет улучшений, нет расходников/ремонта |
| Лимит армии | ✅ да | `ArmyLimit`, правило лобби |
| Обзор / туман войны | ❌ нет | миникарта показывает всех врагов; для режима «коммандер сверху» это сознательно проще |
| Миникарта | ✅ да | клик/перетаскивание = камера, ПКМ = приказ идти; нет пингов и «вспышек» тревоги |
| Звуковые оповещения | ⚠ частично | клик подтверждения, предмет подобран, «не хватает золота»; ✅ добавлено: герой пал / на грани гибели |
| «К последнему событию» | ✅ добавлено | `Backspace` |
| Контекстный курсор (значок атаки над врагом) | ⚠ нет | есть кольцо-подсветка цели и подсказка режима у курсора |
| Тактическая пауза / скорость игры | ❌ нет | только обычная пауза (Esc) |
| Автоматизация (авто-воскрешение, «все простаивающие») | ❌ нет | |

## 3. Что понадобится для мультиплеера (только описание, кода нет)

Готовность текущей архитектуры: **примерно 60–70 %** — разделение и протокол есть, владение героями и проверка на реальном
втором клиенте — нет.

Что уже готово:
* Логика приказов и состояния героев (`HeroBrain`, `OrderService`, `RunFlow`, `ArmyManager`, `Economy`, `LootService`)
  работает только на сервере и не знает про UI и ввод; UI (`ClientRoot`, панели, `ClientInput`) читает только реплицируемое
  состояние (`HcState`, поля `Hero.Net*`). Команда `OrderCommand` сериализуема, есть канал `Net/CommandChannel`
  (сообщения `0x4843/0x4844`), офлайн хост применяет команды напрямую.
* Реплицируются: золото, цены, лимит, состав армии, стойки, маска автоприменения, текущий приказ и кулдауны умений,
  зона телепорта, таймер поражения; лента предметов идёт ручным RPC.
* Правила лобби (`LobbyRules`) и настройки экономики копируются хостом в `HcState`.

Чего не хватает:
1. **Владение.** Сейчас любой клиент может командовать любым героем. Нужны владелец героя / права командира
   (общая армия «все командуют» или у каждого своя) и проверка прав на сервере в обработчике `CommandChannel`.
2. **Несколько командиров.** `LootService.PoolMaster` берёт первого игрока-мастера как общий склад предметов;
   `Run.participatingPlayerCount` и `ThreatPerExtraHero` считают только героев — при нескольких живых командирах нужна
   общая формула; способности командира и их перезарядки хранятся один раз на забег, а не на командира.
3. **Экономика.** Общий кошелёк на всех или у каждого свой; сейчас один.
4. **Клиентская часть.** `ClientRoot` — синглтон на процесс, камера и выделение локальные (так и должно быть), но
   сплит-скрин не поддержан; подключение посреди забега требует проверки восстановления `clientHeroes` по `MasterId`, когда
   мастер героя ещё не заспавнился на клиенте.
5. **Проверка на реальном втором клиенте:** лаги команд, порядок сообщений, смена стадий, выход/вход игрока, рассинхрон
   `Time.time` (кулдауны уже на таймере забега, остальное — проверить).
6. **Безопасность:** все проверки цены/лимита уже на сервере (`ExecRecruit`, `ExecRevive`), но входные данные команд
   (id героев, точки) нужно жёстче валидировать.

Рекомендованный порядок: (а) ввести владельца героя и права; (б) вынести «общий склад» и «кошелёк» в явные объекты армии;
(в) тест с двумя настоящими клиентами; (г) только потом новые возможности.
