## M9 — что сделано
* `Army/HeroRoles.cs` — роли выживших (таблица по `cachedName`) и «сродство» роли к тегам предметов (Damage / Healing / Utility…).
  Таблица ролей перенесена из `BarracksPanel`, казарма использует её же.
* `Army/ItemDistributor.cs` (только сервер):
  * пул = инвентарь командира; каждая новая единица в пуле отдаётся герою с лучшим счётом
    (сродство роли к тегам предмета − 0.10 × число его предметов; павшие герои — в последнюю очередь);
  * режим `ItemSharing = Split` (по умолчанию, у каждой единицы один владелец) / `Mirror` (у всех копия всего);
  * новичок при найме забирает долю у самых «богатых» (`RebalanceOnRecruit`) — в режиме Mirror получает копию пула;
  * ручная передача `Move(item, from, to, count)`, обмен снаряжением `MoveEquipment`, выдача запасного снаряжения
    `EquipFromPool`, полная раздача заново по ролям `RedistributeAll` (самое редкое — первым);
  * снаряжение из пула само уходит героям без снаряжения.
* Хук: `HighCommandRun.OnPoolChanged()` → `Items.Sync(Army)` + `PublishRoster()`; при найме `Items.CatchUp` + `Sync`.
* `HcState`: в реплицируемое состояние добавлен список запасного снаряжения (`SpareEquipment`).
* `UI/InventoryPanel.cs` (клавиша `I`, `Esc` закрывает): строка на героя (портрет, имя, роль, «пал»), ячейка снаряжения и сетка
  предметов (редкие первыми, размер иконок подбирается под число героев/предметов, лишнее — «ещё +N»), подсказки при наведении,
  перетаскивание предмета на строку другого героя (Shift — вся стопка), перетаскивание снаряжения (обмен),
  запасное снаряжение внизу, кнопка «Раздать заново».
* `UI/Tooltip.cs` — общий «immediate-mode» тултип (`Tooltip.Show(...)` каждый кадр, рисует `TooltipView` в `ClientRoot`).
* `UI/PickupIcons.cs` — иконки предметов. **Факт игры 1.5.0:** `PickupDef.iconTexture/iconSprite` пустые, спрайт грузится
  только через Addressables (`PickupDef.GetIconAODR(true)`). Починило и ленту лута (раньше были белые квадраты).
* Настройки (`kantemiir.HighCommand.cfg`): `Loot/ItemSharing`, `Loot/RebalanceOnRecruit`, `Keys/Inventory`.
* Временные (затухающие) предметы из пула превращаются в постоянные, иначе они бы застряли у командира.
* Консоль: `hc_inventory`, `hc_items_move <idГероя> <idГероя> <Предмет> [число]`, `hc_items_auto`.

## M9 — проверено в игре (скрипт, 3 героя: Инженер, Охотница, МУЛ-Т)
* 11 предметов, выпавших в пул, разошлись по трём героям по ролям (Охотнице — урон, МУЛ-Т — лечение/живучесть).
* `hc_items_move` переносит предметы между героями; `hc_items_auto` раздаёт заново.

* Перетаскивание мышью (синтетический ввод `hc_drag`) реально перенесло «57-листный клевер» от Инженера к МУЛ-Т.
* В логе нет исключений и предупреждений от `HighCommand` (остальные `[Error]` — ванильные/чужих модов:
  FixPluginTypesSerialization, ClipCursor, ItemTierDef AssignedAtRuntime, matUIPaintStreakFlash).

## M9 — что осталось
1. **Не проверено в игре** (код есть, прогона не было):
   * `RebalanceOnRecruit` — в тесте предметы падали уже ПОСЛЕ найма; нужно: сначала дропы, потом `hc_recruit`, смотреть `hc_inventory`;
   * режим `ItemSharing = Mirror` (раздача всем + копия пула новичку);
   * снаряжение: дроп снаряжения в пул, авто-выдача героям, обмен перетаскиванием, запасное снаряжение внизу панели;
   * Shift-перетаскивание (вся стопка) и перетаскивание настоящей мышью (проверен только синтетический ввод);
   * подсказки (`Tooltip`): отображаются ли теги `<style=cIsDamage>` и т. п. в описаниях — на скриншоте не проверено;
   * раскладка при > 5–6 героях и при десятках предметов (уменьшение иконок, «+N»);
   * реакция на предметы, которые герой «потратил» (Dio’s и т. п.) — по замыслу не пополняются.
2. **Недоделано:**
   * передача команд от клиента к серверу (в кооперативе `ArmyService.TryMove*` работает только у хоста; нужен
     рукописный Command как у RPC ленты, см. «Сеть»);
   * пустая ячейка снаряжения рисуется чёрным квадратом (можно скрывать/подписывать);
   * баланс раздачи: в тесте вышло 4/5/2 предмета на трёх героев — возможно, поднять штраф за число предметов;
   * переключатель режима раздачи в окне настроек (будет в M10).
3. С чего продолжать: прогнать пункт 1 одним скриптом (дропы → найм → `hc_inventory` → дроп снаряжения →
   `hc_key I` → скриншот), поправить найденное, коммит «M9», затем M10 (командная карточка, окно настроек, умения командира).

## Известные факты об игре (проверено)
* Игра 1.5.0, Unity 2021.3.45. Каталог режимов: ClassicRun, EclipseRun, WeeklyRun, BaseDefenseRun, InfiniteTowerRun + наш.
* У всех 21 ванильного выжившего есть `…MonsterMaster` с ИИ (`MasterCatalog.FindAiMasterIndexForBody`).
* `[ConCommand]` в моде находится только если сборка помечена `[assembly: SearchableAttribute.OptIn]`.
  Флаг `ExecuteOnServer` пересылает команду серверу — в главном меню сервера нет, команда молча пропадает.
* `Run` и `RunArtifactManager` требуют друг друга (RequireComponent) — компонент `Run` заменить нельзя, поэтому
  префаб режима = клон ClassicRun + наш маркер `HighCommandRun`.
* `Stage.RespawnAllNPCs` сам возрождает мастера с `SetDontDestroyOnLoad` у точки старта на новой стадии.
* Капсула: ИИ не жмёт «interact», поэтому выход из капсулы запрашиваем сами (`Interactor.AttemptInteraction(seat)`).
* `ItemTier` кроме классических имеет `FoodTier, Cursed, Page, Hex` (для сортировки — «прочее»).
* `Inventory.SetEquipmentIndex(idx, in EquipmentLocation)`; `EquipmentLocation.zero` = слот 0 набор 0; перегрузки без
  `location` помечены Obsolete.
* Иконки предметов — только через Addressables (см. `UI/PickupIcons.cs`).
* Надпись «COMFORT 35%» на экране — от другого мода пользователя (RoR2Comfort), не от нашего.

## Сеть / кооператив (честная оценка)
* Сервер знает всё; клиентам реплицируются: золото, цены, состав армии, запасное снаряжение (`HcState`), лента лута (RPC).
  Инвентари героев реплицирует сама игра.
* Команды клиента → серверу (приказы, найм, передача предметов) пока вызывают серверный код напрямую, т. е. работают
  только у хоста/в одиночной игре. Нужен транспорт (рукописный Command, как RPC) — пункт M11/M13.

## Разработка
* Git не в PATH: `C:\Users\user\Documents\RoR2Strategy\_tools\mingit\cmd\git.exe`.
* Сборка и установка: `.\tools\build.ps1` (игра должна быть закрыта).
* Скриптовый прогон: положить сценарий в `BepInEx\config\HighCommand.autoexec.txt` и `.\tools\run-game.ps1`
  (`-Pattern`, `-Max`; осторожно: `-Max` обрезает вывод — хвост лога читать прямо из `BepInEx\LogOutput.log`).
  Директивы: `@wait n`, `@scene имя`, `@run`, `@norun`, `@log текст`, `@quit`; остальные строки — консольные команды.
  Координаты `hc_click`/`hc_drag` — экранные пиксели Unity (начало снизу слева): y_unity = 1080 − y_скриншота.
* Скриншоты: `BepInEx\plugins\local-HighCommand\screenshots\`.
