# HighCommand — статус по этапам

Обновляется после каждого этапа. «Проверено» = проверено в игре скриптом (`tools\run-game.ps1` + `HighCommand.autoexec.txt`)
или глазами по скриншоту; «не проверено» = собрано, но в игре не смотрели.

## Что НЕ сделано / ограничения (честно)
* **Правила в лобби** (стартовое золото, множители на экране лобби) — не сделано: `RuleCatalog` собирается внутри игры
  закрытым кодом, патч ради этого признан рискованным. Все числа доступны в `.cfg` и в Mod Options.
* **Кооператив** проверен только на одном компьютере (loopback через собственное соединение хоста). Команды клиентов →
  сервер идут через `Net/CommandChannel`; клиенты видят приказы/стойки/перезарядки героев через реплицируемый ростер.
  Второй настоящий клиент не пробовали.
* **Финальные стадии** (Лунное/Commencement, Пустотные, побег на корабле): герои умеют жать «использовать» на объектах,
  но сценарии финалов рассчитаны на живого игрока и не проверялись. Забег без финала идёт по кругу, как ванильные петли.
* **Два слота снаряжения у МУЛ-Т** в этой сборке игры не воспроизводились (слот один) — ветка по коду готова.
* **ИИ**: ядро — штатные правила навыков каждого выжившего (`AISkillDriver`), поверх них наши правила. Нет кайтинга
  «по-человечески» и избегания зон босса; герои 1–2 уровня без предметов на первых стадиях гибнут от боссов
  (воскрешение за золото, автоотступление смягчают).
* Проверено, но не «до конца»: balance цен/предметов — по формулам и коротким прогонам, не по часовым забегам.

## Известные факты об игре (проверено)
* Игра 1.5.0, Unity 2021.3.45. Каталог режимов: ClassicRun, EclipseRun, WeeklyRun, BaseDefenseRun, InfiniteTowerRun + наш.
* У всех 21 ванильного выжившего есть `…MonsterMaster` с ИИ (`MasterCatalog.FindAiMasterIndexForBody`).
* `[ConCommand]` в моде находится только если сборка помечена `[assembly: SearchableAttribute.OptIn]`.
* `Run` и `RunArtifactManager` требуют друг друга (RequireComponent) — префаб режима = клон ClassicRun + наш маркер.
* `Stage.RespawnAllNPCs` сам возрождает (в том числе павших) мастера с `SetDontDestroyOnLoad` на новой стадии; разбрасывает
  их на ~100 м вокруг точки спавна — `RunFlow` собирает армию у новой точки сбора.
* Капсула: ИИ не жмёт «interact», выход из капсулы запрашиваем сами (`Interactor.AttemptInteraction(seat)`).
* Ванильный game over (`Stage.Update`) требует «заспавненного игрока» — у командира без тела его нет, поэтому
  поражение определяет `RunFlow` (`Run.BeginGameOver(StandardLoss)`); статистику экрана конца забега пишем в `PlayerStatsComponent`.
* Зона телепорта (`HoldoutZoneController`) считает только `isPlayerControlled` тела — патчим `CountPlayersInRadius` /
  `CountLivingPlayers` на живых героев. `TeleporterInteraction.ChargedState` наступает только когда `monstersCleared`.
* `Run.participatingPlayerCount` = число мастеров-игроков (то есть 1 командир): патчим getter под размер армии.
* `NodeGraph.FindClosestNode(..., maxDistance)` может вернуть узел намного дальше лимита → проверяем расстояние сами.
* Первая точка спавна с капсулой находится высоко в небе (y≈750): для «земли» нужен длинный луч вниз / ждать посадки.
* `ItemTier` кроме классических имеет `FoodTier, Cursed, Page, Hex`.
* Снаряжение лежит в «слотах» × «наборах» (`ExtraEquipment`); ванильный подбор кладёт предмет через
  `FindBestEquipmentLocationOrCurrent(defaultPickup)` — `HeroEquipment` делает так же.
* Иконки предметов — только через Addressables (`PickupDef.GetIconAODR`), `iconSprite` пустой.
* Unity `JsonUtility` не знает типов модовой сборки (FixPluginTypesSerialization не работает без сети) — свой `MiniJson`.
* Свои сетевые сообщения: типы UNET 48..88 заняты игрой, берём 0x4843/0x4844.
* `LegacyResourcesAPI` — отдельная сборка `LegacyResourcesAPI.dll`; `JsonUtility` — `UnityEngine.JSONSerializeModule`.
* Команды консоли `spawn_ai`, `time_scale` в этой сборке недоступны (читы выключены).
* Надпись «COMFORT 35%» на экране — от другого мода пользователя (RoR2Comfort), не от нашего.

## Сеть / кооператив (честная оценка)
* Сервер знает всё; клиентам реплицируются: золото, цены, режим раздачи, ростер с приказами/стойками/автоприменением/
  перезарядками, запасное снаряжение, состояние телепорта и таймер поражения, перезарядки способностей командира, лента лута (RPC).
  Инвентари и тела героев реплицирует сама игра.
* Команды клиент → сервер (приказы, найм, передача предметов, воскрешение, телепорт, способности) — `Net/CommandChannel`.
  Проверено только loopback на хосте (`hc_netcmds on`).

## Разработка
* Git не в PATH: `C:\Users\user\Documents\RoR2Strategy\_tools\mingit\cmd\git.exe`.
* Сборка и установка: `.\tools\build.ps1` (игра должна быть закрыта). Пакет: `.\tools\package.ps1`.
* Скриптовый прогон: сценарий в `BepInEx\config\HighCommand.autoexec.txt` и `.\tools\run-game.ps1`
  (`-Pattern`, `-Max`; хвост лога читать прямо из `BepInEx\LogOutput.log`). Директивы: `@wait n`, `@scene имя`, `@run`,
  `@norun`, `@log текст`, `@quit`; остальное — консольные команды. Файл переименовать/удалить после теста, иначе он
  выполнится при следующем запуске игры.
* Координаты `hc_click`/`hc_drag` — экранные пиксели Unity (начало снизу слева): y_unity = 1080 − y_скриншота.
* Скриншоты: `BepInEx\plugins\local-HighCommand\screenshots\`.
* Старый `.cfg` сохраняет прежние значения по умолчанию: при смене дефолтов удалить `kantemiir.HighCommand.cfg`.
